## Frida

The `frida` npm package ships a prebuilt native binding (`frida_binding.node`) that contains frida-core and
frida-gum and the agent library that Frida injects into target processes (`frida-agent.dll`). BEA's own agent script
is compiled at build time with `frida.Compiler` and runs inside that agent.

Frida is distributed under the **wxWindows Library Licence, Version 3.1**, which is the GNU Library General Public
License version 2 (or later) with the wxWindows exception permitting distribution of binary works based on the
library under the user's own terms (SPDX: `LGPL-2.0-or-later WITH WxWindows-exception-3.1`; the npm package declares
`LGPL-2.0 WITH WxWindows-exception-3.1`). The npm package itself contains no license file. Texts:
<https://spdx.org/licenses/LGPL-2.0-or-later.html> and <https://spdx.org/licenses/WxWindows-exception-3.1.html>;
project: <https://frida.re>, source: <https://github.com/frida/frida>. BEA uses the unmodified upstream package.

## `bea-jobhost.exe` (built locally)

`bea-jobhost.exe` is compiled from BEA's own C source (`native/jobhost/bea-jobhost.c`, MIT) by `npm run build` with
the user's MinGW-w64 GCC and linked with `-static`. The executable therefore contains startup code from the MinGW-w64
runtime and, where used, code from libgcc. The MinGW-w64 runtime is distributed under permissive terms (Zope Public
License 2.1 and public-domain/MIT-style notices; see the toolchain's own `COPYING` files) and libgcc under the GNU
GPL version 3 with the GCC Runtime Library Exception, which permits this use. The binary is a build output: it is
never committed and is produced on the user's machine.

## Emulator bridge (installed by the user, never distributed with BEA)

The emulator bridge (`bridge/emu/bea_emu_bridge.py`) is BEA's own MIT-licensed Python code. It imports these packages
from a Python environment that the **user** provides (`BEA_PYTHON`, config `python`, or a BEA-owned virtual
environment that `bea setup --emulator` creates only after the user approves it, from the pinned hashes in
`bridge/emu/requirements.lock`):

| Package    | Version   | License                                                                                                |
| ---------- | --------- | ------------------------------------------------------------------------------------------------------ |
| `unicorn`  | 2.1.4     | Unicorn engine: GNU GPL version 2 (the PyPI metadata of the Python bindings declares a BSD classifier) |
| `capstone` | 5.0.9     | BSD-3-Clause                                                                                           |
| `pefile`   | 2024.8.26 | MIT                                                                                                    |

BEA never vendors, bundles or redistributes Unicorn, Capstone or pefile; it runs the bridge as a separate process and
talks to it over a pipe. Whether that arrangement satisfies a given redistribution scenario is an open legal question
for anyone who packages BEA together with these libraries (DESIGN OI-4).
